========================================
  서버사이드 페이지네이션 정리
  (Spring Boot + MyBatis + PostgreSQL)
========================================

■ 왜 서버사이드인가?

  클라이언트 사이드: 서버에서 전체 데이터(1,000건)를 한번에 받아서 프론트에서 정렬/필터/페이지 처리
  서버사이드:       프론트가 "몇 페이지, 몇 건, 어떤 정렬" 요청 → 서버가 해당 조건만 DB에서 꺼내서 응답

  데이터가 많아지면(1,000건+) 서버사이드가 필수.
  - 네트워크: 항상 20건만 전송 (vs 전체 1,000건)
  - 성능: DB 인덱스로 정렬/필터 (vs JS로 처리)
  - 메모리: 브라우저 부담 없음


========================================
  1. 백엔드 (Spring Boot + MyBatis)
========================================

■ 기술 스택

  - Spring Boot (Java)
  - MyBatis (SQL 매퍼)
  - PostgreSQL (DB, Docker Compose로 5435 포트)
  - Lombok (보일러플레이트 제거)
  - Jackson (JSON 파싱)


■ API 설계

  기존 GET /api/employees                → 전체 조회 (배열 반환)
  추가 GET /api/employees?page=1&size=20 → 서버사이드 (페이지네이션 객체 반환)

  같은 엔드포인트에서 page 파라미터 유무로 분기한다.
  기존 API 연동 페이지 (grid-api)는 그대로 동작.


■ 쿼리 파라미터

  page   : 페이지 번호 (1부터 시작, 필수 - 있으면 페이지네이션 모드)
  size   : 페이지당 건수 (기본 20)
  sort   : 정렬 컬럼명 (id, name, age, position)
  dir    : 정렬 방향 (asc / desc, 기본 asc)
  filter : JSON 배열 [{"field":"name","value":"김"}]


■ 응답 형태 (Tabulator가 요구하는 형식)

  {
    "last_page": 50,       ← 총 페이지 수
    "data": [              ← 현재 페이지 데이터
      { "id": 1, "name": "김민수", "age": 22, "position": "개발자" },
      ...
    ]
  }

  Tabulator는 last_page와 data 필드를 기본으로 인식한다.


■ 엔티티 (Employee.java)

  @Data
  @NoArgsConstructor
  @AllArgsConstructor
  public class Employee {
      private Long id;
      private String name;
      private Integer age;
      private String position;
  }

  Lombok @Data → getter/setter/toString/equals/hashCode 자동 생성


■ 필터 파라미터 DTO (FilterParam.java)

  @Data
  @NoArgsConstructor
  @AllArgsConstructor
  public class FilterParam {
      private String field;    ← 필터 대상 컬럼명
      private String value;    ← 검색어
  }

  프론트에서 넘어오는 filter JSON 배열의 각 요소를 이 객체로 역직렬화한다.


■ 컨트롤러 (EmployeeController.java)

  @RestController
  @RequestMapping("/api/employees")
  @CrossOrigin                          ← CORS 허용 (프론트 5173 ↔ 백엔드 8080)
  @RequiredArgsConstructor
  public class EmployeeController {

      private final EmployeeService employeeService;
      private final ObjectMapper objectMapper;      ← Jackson (JSON 파싱용)

      @GetMapping
      public Object findAll(
          @RequestParam(required = false) Integer page,
          @RequestParam(required = false, defaultValue = "20") Integer size,
          @RequestParam(required = false) String sort,
          @RequestParam(required = false, defaultValue = "asc") String dir,
          @RequestParam(required = false) String filter
      ) throws Exception {
          if (page != null) {
              List<FilterParam> filters = null;
              if (filter != null && !filter.isBlank()) {
                  filters = objectMapper.readValue(
                      filter,
                      new TypeReference<>() {}
                  );
              }
              return employeeService.findPaginated(page, size, sort, dir, filters);
          }
          return employeeService.findAll();
      }
  }

  핵심 포인트:
  - page != null 이면 findPaginated, 아니면 findAll (기존 전체조회)
  - filter 문자열을 Jackson ObjectMapper로 List<FilterParam>으로 변환
  - @CrossOrigin 으로 CORS 처리 (NestJS의 enableCors()에 해당)
  - @RequestParam(required = false) → 파라미터 없어도 에러 안 남
  - 반환타입 Object → 전체조회(List) / 페이지네이션(Map) 분기 가능


■ 서비스 - findPaginated (EmployeeService.java)

  private static final Set<String> VALID_COLUMNS = Set.of(
      "id", "name", "age", "position"
  );

  public Map<String, Object> findPaginated(
      int page, int size, String sort, String dir, List<FilterParam> filters
  ) {
      // 1) 컬럼 검증 (SQL Injection 방지!)
      String sortCol = (sort != null && VALID_COLUMNS.contains(sort))
          ? sort : "id";
      String sortDir = "desc".equalsIgnoreCase(dir) ? "DESC" : "ASC";

      // 2) 필터 컬럼 검증
      if (filters != null) {
          filters.removeIf(f -> !VALID_COLUMNS.contains(f.getField()));
      }

      // 3) 총 건수 조회 (COUNT)
      int total = employeeMapper.count(filters);

      // 4) OFFSET 계산 + 데이터 조회
      int offset = (page - 1) * size;
      List<Employee> data = employeeMapper.findPaginated(
          filters, sortCol, sortDir, size, offset
      );

      // 5) Tabulator 형식으로 반환
      int lastPage = (int) Math.ceil((double) total / size);
      return Map.of("last_page", lastPage, "data", data);
  }

  핵심 포인트:
  - VALID_COLUMNS Set으로 허용된 컬럼만 사용 (SQL Injection 방지)
  - NestJS/Drizzle 버전과 달리 SQL 쿼리는 MyBatis XML에서 처리
  - Map.of("last_page", ..., "data", ...) → Jackson이 자동으로 JSON 변환


■ 매퍼 인터페이스 (EmployeeMapper.java)

  @Mapper
  public interface EmployeeMapper {

      @Select("SELECT * FROM employees ORDER BY id")
      List<Employee> findAll();

      // 페이지네이션용 (XML에 정의)
      int count(@Param("filters") List<FilterParam> filters);

      List<Employee> findPaginated(
          @Param("filters") List<FilterParam> filters,
          @Param("sortCol") String sortCol,
          @Param("sortDir") String sortDir,
          @Param("limit")   int limit,
          @Param("offset")  int offset
      );
  }

  핵심: count, findPaginated는 동적 SQL이 필요 → XML 매퍼에 정의
  (어노테이션으로는 <if>, <foreach> 같은 동적 SQL 작성이 어려움)


■ MyBatis XML 매퍼 (EmployeeMapper.xml)

  <!-- 필터 WHERE 조건 (재사용 가능한 SQL 조각) -->
  <sql id="filterWhere">
      <if test="filters != null and filters.size() > 0">
          WHERE
          <foreach collection="filters" item="f" separator=" AND ">
              ${f.field} LIKE CONCAT('%', #{f.value}, '%')
          </foreach>
      </if>
  </sql>

  <!-- 총 건수 -->
  <select id="count" resultType="int">
      SELECT COUNT(*) FROM employees
      <include refid="filterWhere"/>
  </select>

  <!-- 페이지네이션 데이터 -->
  <select id="findPaginated" resultType="com.hyun.fnb.employee.Employee">
      SELECT * FROM employees
      <include refid="filterWhere"/>
      ORDER BY ${sortCol} ${sortDir}
      LIMIT #{limit} OFFSET #{offset}
  </select>

  핵심 포인트:
  - <sql id="filterWhere"> → count와 findPaginated에서 공통 사용
  - ${f.field} → 컬럼명은 ${}(문자열 치환). 서비스에서 검증 완료했으므로 안전
  - #{f.value} → 값은 #{}(PreparedStatement 바인딩). SQL Injection 방지
  - #{limit}, #{offset} → 바인딩 변수로 안전하게 전달
  - CONCAT('%', #{f.value}, '%') → PostgreSQL의 LIKE 패턴


  $ vs # 차이 (MyBatis 핵심):
  ┌──────────┬──────────────────────────┬──────────────────────────┐
  │          │ ${...}                   │ #{...}                   │
  ├──────────┼──────────────────────────┼──────────────────────────┤
  │ 동작     │ 문자열 그대로 치환       │ PreparedStatement ?      │
  │ 용도     │ 컬럼명, 테이블명, ASC    │ 값 (검색어, LIMIT 등)    │
  │ 보안     │ SQL Injection 위험!      │ 안전                     │
  │ 예시     │ ORDER BY ${sortCol}      │ WHERE name LIKE #{value} │
  └──────────┴──────────────────────────┴──────────────────────────┘
  → ${} 쓸 때는 반드시 자바 코드에서 화이트리스트 검증 필수!

========================================
  2. 프론트엔드 (Tabulator 서버사이드 모드)
========================================

■ 핵심 설정 옵션

  const API_URL = "http://localhost:8080/api/employees";   ← Spring Boot는 8080 포트!

  const table = new Tabulator(el, {
    // 페이지네이션 ON + 서버사이드
    pagination: true,            ← 이거 없으면 페이지네이션 UI 안 나옴!
    paginationMode: "remote",    ← 서버에서 데이터 받기
    paginationSize: 20,          ← 페이지당 건수
    paginationSizeSelector: [10, 20, 50, 100],  ← 사용자 선택 UI

    // 정렬/필터도 서버사이드
    sortMode: "remote",
    filterMode: "remote",

    // 서버 URL
    ajaxURL: API_URL,            ← http://localhost:8080/api/employees

    // 커스텀 요청 함수
    ajaxRequestFunc: (url, config, params) => { ... },
  });


■ ajaxRequestFunc — 왜 필요한가?

  Tabulator가 기본으로 보내는 파라미터 형태와 우리 서버가 받는 형태가 다르다.
  ajaxRequestFunc로 요청을 직접 구성한다.

  ajaxRequestFunc: (url, _config, params) => {
    // params에 들어오는 값:
    // params.page    → 현재 페이지 (1, 2, 3...)
    // params.size    → 페이지 크기 (20)
    // params.sorters → [{ field: "name", dir: "asc" }]  ← sort 아님! sorters!
    // params.filters → [{ field: "name", type: "like", value: "김" }]

    const query = new URLSearchParams();
    query.set("page", String(params.page || 1));
    query.set("size", String(params.size || 20));

    if (params.sorters && params.sorters.length > 0) {
      query.set("sort", params.sorters[0].field);
      query.set("dir", params.sorters[0].dir);
    }

    if (params.filters && params.filters.length > 0) {
      const filters = params.filters.map(
        (f: { field: string; value: string }) => ({
          field: f.field,
          value: f.value,
        })
      );
      query.set("filter", JSON.stringify(filters));
    }

    return fetch(`${url}?${query.toString()}`)
      .then(res => res.json());
  }

  주의: params.sort가 아니라 params.sorters 이다!


■ 헤더 필터 (headerFilter)

  컬럼 정의에 headerFilter를 추가하면 헤더 아래에 입력란이 생긴다.
  사용자가 타이핑하면 자동으로 서버에 필터 요청이 간다.

  columns: [
    { title: "이름", field: "name", headerFilter: "input" },
    { title: "직책", field: "position", headerFilter: "input" },
  ]


■ 서버 응답 형식

  Tabulator remote 모드는 이 형태를 기대한다:
  {
    "last_page": 50,    ← 필수! 총 페이지 수
    "data": [...]       ← 필수! 현재 페이지 데이터
  }

  이 두 필드가 없으면 데이터가 안 나온다.


========================================
  3. 데이터 흐름 정리
========================================

  [사용자가 2페이지 클릭]
      ↓
  [Tabulator] ajaxRequestFunc 호출
      params = { page: 2, size: 20, sorters: [...], filters: [...] }
      ↓
  [fetch] GET /api/employees?page=2&size=20&sort=name&dir=asc
      ↓
  [Spring Boot Controller] page != null → findPaginated 호출
      ↓
  [Service] 컬럼 검증 후 MyBatis Mapper 호출
      ↓
  [MyBatis] SQL 실행 (EmployeeMapper.xml)
      SELECT COUNT(*) FROM employees WHERE name LIKE '%김%'
      SELECT * FROM employees WHERE name LIKE '%김%'
             ORDER BY name ASC LIMIT 20 OFFSET 20
      ↓
  [Service] Map.of("last_page", 50, "data", [...20건...])
      ↓
  [Jackson] Map → JSON 자동 변환
      { "last_page": 50, "data": [...] }
      ↓
  [Tabulator] 테이블 렌더링 + 페이지네이션 UI 업데이트


========================================
  4. 시드 데이터 (1,000건)
========================================

  schema.sql → 테이블 생성 (CREATE TABLE IF NOT EXISTS employees)
  data.sql   → 1,000건 INSERT

  spring.sql.init.mode=always 설정으로 앱 시작 시 자동 실행.

  이름: 성(10개) × 이름(10개) 조합 → "김민수", "이지은", "박서연"...
  나이: 22~51세 반복
  직책: 개발자, 디자이너, 기획자, 매니저, 마케터, 영업, QA, 데이터분석가, DevOps, 인턴

  PostgreSQL이므로 변수 제한 없이 한번에 INSERT 가능.
  (data.sql에 1,000건의 VALUES 직접 나열)

  └──────────────────┴────────────────────────┴────────────────────────┘


========================================
  6. 트러블슈팅
========================================

  Q: 데이터가 안 나온다 (빈 테이블)
  A: 브라우저 콘솔(F12)에서 에러 확인.
     - CORS 에러 → 컨트롤러에 @CrossOrigin 어노테이션 확인
     - 404 → 백엔드 서버(8080번 포트) 떠있는지 확인
     - 응답 형식 → { last_page, data } 형태인지 확인

  Q: 페이지네이션 UI가 안 나온다
  A: pagination: true 설정이 반드시 있어야 한다.
     paginationMode: "remote"만으로는 부족.

  Q: 정렬이 안 된다
  A: ajaxRequestFunc에서 params.sorters (O) vs params.sort (X) 확인.
     Tabulator 6.x는 sorters 배열로 전달.

  Q: 필터가 안 된다
  A: ajaxRequestFunc에서 params.filters 확인.
     서버에서 ObjectMapper로 filter 쿼리파라미터를 List<FilterParam>으로 파싱하는지 확인.

  Q: DB 연결 에러
  A: Docker Compose로 PostgreSQL 컨테이너가 떠있는지 확인.
     포트 5435, DB명 fnb, 계정 fnb / fnb1234

  Q: MyBatis 매퍼를 못 찾는다
  A: application.properties에 mybatis.mapper-locations=classpath:mapper/*.xml 확인.
     XML의 namespace가 EmployeeMapper 인터페이스 패키지와 일치하는지 확인.
